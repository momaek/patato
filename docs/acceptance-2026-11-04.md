每条路径执行四项检查，均不自动重试、不放宽断言：

1. 访问 HTTPS IP 字面量目标，核对实际出口是否为指定节点。
2. 访问公共域名 HTTPS 目标，核对出口，验证代理侧域名解析。
3. 下载 65536 字节固定载荷，核对全部字节及 SHA-256：`7daca2095d0438260fa849183dfc67faa459fdf4936e1bc91eec6b281b27e4c2`。
4. 通过 SOCKS5 UDP ASSOCIATE 发送带随机 nonce 的单个报文，核对回显。

## 已修复与未解决问题

### Linux local DNS 修复

一台 Linux 节点的 resolv.conf 遗留注释使 sing-box 选择了实际未运行的 systemd-resolved D-Bus 服务。相同真实 Linux 测试在旧实现中，IP 请求成功而 localhost 请求失败，日志包含 `org.freedesktop.resolve1 was not provided by any .service files`。

修复为 local DNS 显式设置 `prefer_go: true`，按 hosts/resolv.conf 解析，不依赖该 D-Bus 服务。现有协议测试同时覆盖 IP 与 localhost；修复后真实 Linux 七个协议用例全部通过。本机 node/nodeapi 非缓存测试、node race 测试、gofmt 和 git diff --check 通过。本轮没有重跑全部服务端、前端及支付集成测试。

### DNS 传播仍未收口

测试域名的权威 A 记录正确，部分递归解析也已正确，但不同地点及 A/AAAA 的负缓存仍不一致。撤销 hosts 时，节点首选解析器实际返回旧 SOA 的 NXDOMAIN，另一节点也记录了 exchange4 NXDOMAIN，不能宣称公共 DNS 已全面生效。

四台节点最终仅保留针对测试 API 名称的单条 hosts 映射，没有修改全局 nameserver。**测试 API 的跨代理载荷下载依赖此映射**；独立公共域名的代理 DNS 检查不依赖它。后续须在每台节点的递归解析稳定后撤销映射并复测。

### 其余限制

- 间歇 HTTPS 异常与 UDP 超时尚未定位；后续成功不能替代稳定性证据。
- HY2 使用自签测试证书，订阅允许 insecure TLS，尚未验证正式证书链。
- 服务端与节点是持久 systemd 服务；中转与客户端是 transient 单元，当前运行不等于整机重启后自动启动。
- 测试服务设置了资源上限。检查时既有业务服务仍运行、原端口仍监听，但未对既有业务做完整功能回归。
